# 묻고 답하기 — 사용자의 질문 형태별로 무엇을 읽는가

전부 읽기 전용이다. 아래 표의 `kadan`은 PATH에 없으면 `node <저장소>/src/cli.mjs`로
치환한다. 원장·화면 원문을 근거로 답하고, 추측하지 않는다. 모르면 모른다고 한다.

## "지금 어떻게 돼가?"

```bash
kadan tree
kadan status
```

- `tree`에서 판별 역할과 카드 상태(보냄/done)를 읽는다.
- `status`에서 세션 생존과 PID 일치를 읽는다.
- watch가 떠 있어야 하는 판이면 `pgrep -x kadan-watch`로 감시 생존도 확인한다.

## "이거 누가 시켰어?"

```bash
kadan log
```

원장의 `by → 역할` 열을 읽는다(card-28). `by`는 스스로 밝힌 신분이다 —
watch 내부 전달이면 `watch`, 카단 세션 안이면 그 역할, 둘 다 아니면 `사람`.
비서가 전달한 것은 `비서`다(비서는 발송에 `KADAN_ROLE=비서`를 붙인다).
`by`가 없는 옛 줄은 `모름`으로 읽는다. 사람으로 추측하지 않는다.

## "이거 왜 이래?"

```bash
kadan read <역할> --lines 30
kadan log
```

화면 마지막 줄과 원장의 최근 흐름을 같이 본다. 화면만 보고 판단하지 않는다 —
화면은 지금 상태, 원장은 지나온 순서다.

## "밀린 거 있어?"

```bash
kadan tree
```

`tree`에서 `보냄 HH:MM (완료 없음)`으로 남은 카드를 찾는다. 그 카드가 밀린
것이다. done이 찍힌 카드는 끝난 것이다.

## "왜 조용해?"

```bash
pgrep -x kadan-watch
kadan status
kadan read <조용한 역할> --lines 15
```

- watch PID가 없으면 감시가 죽은 것이다 — 슈퍼감독에게 전한다(비서가 직접
  재가동하지 않는다).
- 세션이 죽었거나 PID가 바뀌었으면 그 사실을 그대로 보고한다.
- 세션이 살아 있고 화면이 입력 대기면 정상 대기일 수 있다 — 감독·검수자의
  정상 대기를 정체로 오판하지 않는다(잠긴 규칙 8).
- **화면 마지막 줄에 제공자 오류가 있으면 정체가 아니라 끊김이다** — 아래 절로 간다.

## "멈춘 것 같은데?" — 끊김인지 먼저 가른다

사용자는 이동하며 작업해서 **인터넷이 자주 끊긴다. 이건 상시 조건이지 사고가 아니다.**
화면 마지막 줄에 아래가 보이면 끊김이다(2026-08-31 실측; 서명 원본은 `src/watch.mjs`의 끊김 서명):

```text
502 Bad Gateway · Provider unreachable · getaddrinfo ENOTFOUND
429 Too Many Requests · stream error · stream disconnected · exceeded retry limit · rate limit
```

끊김으로 보이면 **정말 끊긴 것인지 셋을 확인하고 사용자께 구분해 보고한다**:

```bash
ping -c 1 -t 3 1.1.1.1          # 인터넷 자체
nslookup <오류에 찍힌 호스트>      # 이름 풀이
lsof -nP -iTCP:<포트> -sTCP:LISTEN # 프록시 생존
```

- 셋 다 정상인데 화면만 그 오류면 **그 순간만의 끊김**이다. "지금은 풀렸다"까지 함께 보고한다.
- 하나라도 진짜 죽어 있으면 **끊김이 아니라 고장**이다. 그대로 보고한다.
- **비서는 다시 돌리라고 스스로 지시하지 않는다.** 다시 돌리는 것은 감독의 판단이고,
  사용자가 시키면 그때 슈퍼감독에게 전한다(2026-08-31 실측: 비서가 진단하고 사용자 지시로 전달했다).

## 답할 때

- 결론 먼저, 쉬운 말 먼저, 읽은 명령과 원문을 근거로 붙인다.
- 화면·원장에 없는 것은 지어내지 않는다. "원장에 없어서 모른다"가 답이다.
