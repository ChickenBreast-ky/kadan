# 비서 공식 우편함

## Why

[kyle]의 주 대화 상대인 비서가 슈퍼감독의 공식 회신을 화면 조회에만 의존하지 않고 받아 확인할 수 있도록 한다.

비서는 우편 주소이며 tmux 역할 세션을 새로 만들지 않는다. 세션 생존·정체 감시 대상이 아니다. 사용자 일반 대화나 전체 터미널 대화는 수집하지 않는다. 작업 요청·결정 전달·공식 보고만 명시적으로 우편을 보낸다.

```sh
KADAN_ROLE=판-슈퍼감독 kadan send 비서 --mail-kind report '현재 작업 마감. 전환 준비 완료.'
KADAN_ROLE=비서 kadan inbox list
KADAN_ROLE=비서 kadan inbox read <우편ID>
KADAN_ROLE=비서 kadan inbox ack <우편ID>
```

- `--mail-kind`: request/decision/report. 생략 시 report. 분류를 적는 것이 사용자 결정을 대신 승인하는 것은 아니다. 정식 사용자 결정 요청/답변은 기존 decision CLI를 유지한다.
- `--reply-to`: 기존 우편의 mailId 또는 digest를 참조할 수 있다. 기존 요청과 연결할 때 쓴다. 없는 참조는 거절한다.
- `send 비서 --task`는 거절한다. 비서에게 작업 실행을 발령하는 기능이 아니다.
- `--work 저장소/업무ID`, `--execution 저장소/실행ID`로 [업무 카드](business-work.md)에 연결할 수 있다. 기존 SQLite 우편을 업무 안에서 함께 보는 것이며 별도 인박스를 만들지 않는다. 답장에는 원본의 업무·실행 연결을 이어받는다. 여러 통에 겹치는 지문은 고유한 우편 ID로 구분한다.
- inbox list 기본값은 미확인. `--all 1`로 전체를 볼 수 있다. read는 본문 조회만 하며 자동 읽음 처리하지 않는다. 비서가 내용을 확인한 뒤 ack를 실행한다. ack는 작업 완료나 지시 승인과 별개다.
- 우편 내용은 `mail/<sha256>.txt`에 0600으로 저장한다. 원장 send에는 mailId·분류·수신자·발신자·본문 지문 등만 두며 비서 수신 우편의 본문/미리보기는 원장에 복사하지 않는다. 다른 기존 우편의 미리보기 형식은 그대로다.
- 조회/본문 오류는 미확인으로 남긴다. 일반 대화 자동 저장, 백그라운드 AI 폴링, OS 포커스 변경, 새 비서 프로세스 생성은 없다.

## 전달과 깨움의 경계

send 결과 `stored`는 우편함에 저장됐다는 뜻이다. 현재 사용자와의 이 대화창에 직접 입력하거나 자동으로 깨우는 연결은 없으므로 `wake: not-connected`를 명시한다. 비서는 사용자의 다음 요청 처리 때 미확인 우편을 읽는다. 시간이 중요한 알림은 기존 사용자 알림 경로를 유지한다.

우편함 화면의 ‘비서와 주고받은 공식 우편’에서 조회할 수 있다. 수신 우편은 저장됨/비서 미확인/비서 확인함으로 구분한다. 슈퍼감독은 회신을 비서에게 보낸 뒤 대기를 위해 반복 조회하지 않는다.

## 저장 전환 호환

비서 우편 사건과 읽음은 공통 appendLedger/readLedger를 사용한다. SQLite 전환 시 같은 시스템 사건 스트림으로 옮겨진다. 본문 파일은 그대로 보존한다. `transport: mailbox` 사건은 실행·세션 나무에서 제외되며 감시에는 start 기록이 없어 들어가지 않는다.

대시보드 상단의 **비서 미확인 보고**는 사용자 결정 수와 별도로 집계한다. 클릭하면 비서 미확인 우편만 보여준다. 조회만으로 읽음 처리하지 않으며, 원장 손상은 0건 대신 모름으로 표시한다.
