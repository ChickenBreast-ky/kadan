# 기록보기 중 전송 보류

## Why

사용자가 기록을 읽는 동안 전송이 선택·스크롤을 건드리지 않게 하고, 키를 보낸 사실과 실제 입력 접수를 구분한다.

tmux 전송은 본문 준비 전, 붙여넣기 직전, Enter 직전에 `pane_in_mode`를 확인한다.
복사모드 등 기록보기 상태이거나 조회가 실패하면 전송을 보류한다. 프로그램은 기록보기를
강제로 해제하거나 선택을 복사하지 않으며, 본문과 Enter를 자동 재전송하지 않는다.

- 본문 붙여넣기 전 중단: `delivery=not-sent`. 본문·Enter를 보내지 않았다.
- 붙여넣기 시도 이후 중단: `delivery=unknown`, `sendStage`에 단계가 남는다.
  본문 일부가 입력창에 있을 수 있지만 입력 제출은 미확인이다. 성공 send 원장을 쓰지 않는다.
- 정상 경로: CLI는 `키 전송됨 — 입력 접수·AI 실행 미확인`을 표시한다.
  send 원장의 `keyDelivery=sent`, `inputAcceptance=unconfirmed`는 tmux 키 전달 사실만 뜻한다.
  실제 입력 접수·AI 실행 성공·작업 완료를 증명하지 않는다.

보류 뒤에는 기록보기와 원래 보내려던 내용·현재 사용자 입력을 사람이 확인한다.
남은 텍스트만 보고 Enter를 보내거나 자동 재시도하지 않는다. 기록보기를 벗어나도
이전 전송을 자동 재개하지 않는다. 기존 원장의 과거 send 의미와 이력은 소급 변경하지 않는다.

모드 검사와 실제 paste/Enter는 각각 다른 tmux 명령이므로 마지막 검사 뒤에도 모드나
사용자 입력이 바뀔 수 있다. 이 경합을 완전히 없애거나 AI 입력 접수를 확인하는 기능은 아니다.
모델별 화면 해석·사용자 입력 강제 제출·Rottie 데몬 변경은 추가하지 않는다.
이 방어가 과거 특정 사고의 원인이 복사모드였다는 증명은 아니다.
