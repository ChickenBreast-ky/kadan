# Why

[kyle]이 카드와 기록을 조밀하게 훑으면서도, 화면마다 달라지는 버튼 크기 때문에 헷갈리지 않고 필요한 조작을 쉽게 찾도록 공통 기준을 둔다.

## 제품과 적용 범위

| 항목 | 카단 라이트 기준 |
|---|---|
| 서비스 | 여러 AI 역할의 카드·진행·기록을 확인하는 업무 도구 |
| 핵심 행동 | 카드를 찾고, 목적·진행·차례를 읽고, 필요한 원문을 펼친다 |
| 주 사용 환경 | PC, 작은 화면에서도 열람 가능 |
| 정보 밀도 | 조밀한 표형 기본, 목록·상세와 문서형 선택 유지 |
| 기존 구조 | Node가 HTML과 CSS 문자열을 렌더한다. 별도 UI 프레임워크는 없다 |
| 공통 기준 | `src/ui-foundation.mjs`의 `uiFoundationStyle` |
| 연결 위치 | `src/center-wall.mjs`에서 기존 화면 스타일 뒤에 포함 |
| 첫 적용 | 카드 목록·상세의 버튼과 입력, 기록 화면, 카드 저장, 질문 복사 |
| 배치 소유 | `dashboard-workspace-style.mjs`, `dashboard-detail-style.mjs` 등 기존 화면 파일 |

참고한 개인 디자인 시스템 초안의 역할 구분을 가져왔다. 예시의 파란색·44px 기본 크기는 제품에 맞게 바꿨다. 새 의존성은 추가하지 않았다. 참고용 옛 화면인 `legacy=1`은 적용 대상에서 제외한다.

## 글씨와 누르는 영역

아래 크기는 브라우저 기본 글씨가 16px인 경우다. 최상위 글씨를 `100%`로 두고 공통 값은 `rem`을 사용한다. 부모 영역의 글씨와 버튼의 글씨는 별개다.

| 역할 | 크기 | 굵기·줄높이 | 적용 |
|---|---:|---|---|
| 대표 제목 | 20px | 700 / 1.3 | 카드 상세 제목, `.ds-title` |
| 영역 제목 | 15px | 700 / 1.4 | `.ds-heading` |
| 기본 본문 | 14px | 400 / 1.55 | 공통 바탕 |
| 보조 설명 | 12px | 400 / 1.5 | `.ds-caption` |
| 일반 버튼 | 13px | 600 / 1.4 | 저장·일반 조작 |
| 보조 버튼 | 12px | 600 / 1.4 | 보기 전환·닫기·원문·갱신 |
| 버튼 안 강조 | 버튼 크기 유지 | 700 | 버튼 내부 `strong` |

| 누르는 영역 | PC | 터치 입력 환경 |
|---|---:|---:|
| 일반 버튼 | 최소 32px | 최소 44px |
| 보조·아이콘 버튼 | 최소 28px | 최소 44px |
| 카드 표 행 | 38px | 최소 45px |
| 기록 표 행 | 34px | 최소 45px |

PC의 조밀한 업무 화면에는 32px·28px를 사용한다. 터치 환경은 화면 너비가 아니라 `pointer: coarse`로 구분하며 너비와 높이 모두 44px 이상을 확보한다. 긴 버튼 문구는 줄바꿈으로 높이가 늘어난다. 버튼을 작게 보이게 하려고 중요한 문구를 자르지 않는다.

예외: 표 머리글과 기록 미리보기 버튼은 열·행 전체가 누르는 영역이다. 날짜·카드 ID·긴 지시문 등 기존 읽기 영역의 세부 글씨 크기는 화면 파일에서 유지한다. 이 문서는 모든 기존 읽기 스타일을 공통 변수로 옮겼다는 뜻은 아니다.

## 색·간격·형태

| 역할 | 값 |
|---|---|
| 화면 배경 / 표면 | `#f5f6f7` / `#ffffff` |
| 글씨 / 보조 글씨 | `#202724` / `#536159` |
| 테두리 | `#cbd5ce` |
| 핵심 행동 / 그 위 글씨 | `#21684e` / `#ffffff` |
| 보조 행동 배경 | `#eef5f1` |
| 간격 | 4·8·12·16·24·32px |
| 버튼 모서리 | 5px |
| 패널 모서리 기본값 | 8px |

버튼 색은 행동의 강조를 표현한다. 카드 상태와 실행 결과의 기존 색 의미는 별도로 유지한다. 입력창 테두리·글씨와 공통 제목도 같은 변수에서 읽는다.

## 공통 조작의 사용법

기존 구성 요소는 공통 스타일 안의 선택자로 역할에 연결했다. 화면마다 버튼의 글씨·높이·여백을 다시 선언하지 않는다. 새 조작은 다음처럼 사용한다.

```html
<button type="button">일반 조작</button>
<button type="button" class="ds-button--primary">확인</button>
<button type="button" class="ds-button--compact">닫기</button>
<button type="button" class="ds-button--quiet">원문 보기</button>
<button type="button" disabled aria-busy="true">저장 중…</button>
<a class="ds-button ds-button--compact" href="#ledger">기록 보기</a>
```

- 모든 예시는 `.dw-shell` 안에서 적용된다. 이름만 다른 전역 버튼 체계를 추가하지 않는다.
- 폼 제출 버튼은 강조형이다. 제출이 아닌 조작에는 `type="button"`을 쓴다.
- 버튼은 내용에 맞는 너비를 쓰며, 폼이 넓다고 버튼도 자동으로 늘어나지 않는다.
- 선택된 탭은 밑줄과 글씨 색, 보기 전환은 선택 배경으로 구분한다.
- 비활성 상태는 흐리게 표시한다. 처리 중에는 비활성 여부와 별개로 `aria-busy`를 명시할 수 있다. 실제 입력 차단은 기존 저장 동작이 담당한다.
- 키보드 포커스는 녹색 외곽선이다. 원문을 닫으면 열었던 버튼으로 돌아간다.
- 목록 선택, 드래그, 원문 펼침, 상세 전환, 실패 시 입력 보존은 기존 클라이언트 코드가 담당한다. 공통 CSS는 그 동작을 바꾸지 않는다.
- 현재 별도의 공통 팝업은 없다. 브라우저 확인창과 페이지 안 펼침 동작을 사용한다.

## 수정 규칙

1. 글꼴·크기·굵기·줄높이를 각각 정한다. 버튼에 `font: inherit`를 다시 넣지 않는다.
2. 크기와 강조 종류가 필요하면 먼저 공통 역할로 표현한다. 새 역할이 필요할 때 이 파일과 `ui-foundation.mjs`를 함께 고친다.
3. 화면 파일에는 정렬, 너비 분할, 표 열, 스크롤 등 배치를 둔다. 버튼의 모양과 글씨 기준을 다시 덮어쓰지 않는다.
4. 넓은 `!important`로 충돌을 숨기지 않는다. 먼저 기존 선언을 찾아 소유 위치를 정리한다.
5. 제품의 카드·상태 데이터와 UI 크기를 섞지 않는다. 본문 크기가 버튼 크기를, 기록 작성자가 현재 차례를 결정하지 않는다.

### 운영 흐름 탭의 원본 디자인 적용 (2026-09-09)

[kyle]가 제공한 HTML 원본을 우선하도록 요청했다. 운영 흐름은 상황 설명과 관계도를 읽는 화면이므로, `.of-page` 안에서 아래 시각 기준을 사용한다. 기존 작업·결정·기록 탭과 공통 조작 크기는 유지한다.

- 배경 `#f5f6fb`, 글씨 `#202d48`, 보조 글씨 `#63718b`, 테두리 `#dce2f0`, 선택 강조 `#5754dc`, 선택 배경 `#f0efff`.
- 원본의 큰 제목, 여백, 네 칸 관계도, 선택한 근거 패널을 사용한다. 관계도 칸과 업무 선택 항목은 내용 전체가 누르는 영역이므로, 전용 여백·모서리·제목 크기를 `operations-flow-view.mjs`에서 정한다.
- 글꼴과 일반 버튼·입력의 크기, 터치 영역은 공통 기준을 상속한다. 새 전역 버튼 체계는 만들지 않는다.
- 완료 보고·중앙 업무 마감·인수 수락을 따로 표시한다. 우편 수를 완료 보고 수로 쓰거나, 미확인을 실행 중·실패로 바꾸지 않는다.

## 2026-09-08 확인

원인은 공통 `font: inherit`, 최상위 글씨 중복 선언, 화면별 버튼 여백·크기의 중복이었다. 변경 전 같은 저장 조작이 상세에서는 약 36.6px, 새 카드에서는 41.25px였다.

- 큰 글씨 28px 영역과 작은 글씨 12px 영역에 놓은 버튼: 모두 글씨 13px, 굵기 600, 줄높이 18.2px, 높이 32px.
- PC 보기 전환·상세 조작·닫기·갱신: 글씨 12px, 높이 28px. 새 카드 저장: 글씨 13px, 높이 32px.
- 긴 한글·영문 문구는 줄바꿈되고 가로 잘림이 없었다. 비활성 버튼과 버튼 내부 강조를 확인했다.
- Tab 포커스 표시, Enter 실행, 원문을 닫은 뒤 초점 복귀를 확인했다.
- 390px 너비와 터치 입력을 브라우저에서 재현해 주요 버튼의 44×44px 이상 영역을 확인했다. 실제 휴대폰 기기 확인은 아니다.
- 사용자 글씨 200%에서는 같은 일반 버튼들이 26px로 함께 커졌다. CSS 배율 200%에서도 주요 조작 문구와 페이지 바깥 넘침을 확인했다. 브라우저 메뉴의 확대 단축키로 검사한 것은 아니다.
- 기존 전체 검사 `node --test tests/*.test.mjs`: 369개 통과. 별도 빌드·타입 검사나 UI 라이브러리 설치 단계는 없다.
- 자동 검증은 OS 창 포커스를 옮기지 않았으며 실제 서비스 POST는 없었다.
